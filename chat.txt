what is meant by agentic workframes in this job listing "Building & Delivery
Build, integrate, and maintain AI-powered features and workflows, leveraging LLM APIs (OpenAI, Anthropic, etc.), RAG pipelines, and agentic frameworks."

In that context, “agentic frameworks” (often what people mean by “agentic workflows”) refers to systems where an AI model doesn’t just respond once, but acts more like an autonomous agent that can plan, take actions, and iterate toward a goal.

What “agentic” means

An agentic system typically:

Receives a goal (not just a single prompt)
Breaks it into steps (planning)
Uses tools (APIs, databases, code execution, etc.)
Observes results
Adjusts and continues until the task is complete

So instead of:

“Generate an answer to this question”

You get:

“Figure out how to solve this task end-to-end, using available tools if needed”

What an “agentic framework” is

An agentic framework is a toolkit or architecture that helps you build those systems.

Common examples include:

LangChain
AutoGen
CrewAI
Semantic Kernel

These frameworks provide:

Tool calling / function execution
Memory (short-term + long-term context)
Planning loops (reason → act → observe)
Multi-agent coordination (agents talking to each other)

Example (Python skeleton)
from langchain.document_loaders import WebBaseLoader
from langchain.vectorstores import FAISS
from langchain.embeddings import OpenAIEmbeddings
from langchain.chains import RetrievalQA
from langchain.chat_models import ChatOpenAI

# Load data
loader = WebBaseLoader("https://example.com/article")
docs = loader.load()

# Embed + store
embeddings = OpenAIEmbeddings()
vectorstore = FAISS.from_documents(docs, embeddings)

# Create QA chain
qa = RetrievalQA.from_chain_type(
    llm=ChatOpenAI(),
    retriever=vectorstore.as_retriever()
)

response = qa.run("Summarize key insights")
print(response)

from crewai import Agent, Task, Crew

researcher = Agent(
    role="Researcher",
    goal="Find relevant information",
    tools=[rag_tool]
)

analyst = Agent(
    role="Analyst",
    goal="Extract insights"
)

writer = Agent(
    role="Writer",
    goal="Write structured report"
)

tasks = [
    Task(description="Research topic: AI in healthcare", agent=researcher),
    Task(description="Analyze findings", agent=analyst),
    Task(description="Write report", agent=writer),
]

crew = Crew(agents=[researcher, analyst, writer], tasks=tasks)
result = crew.kickoff()

Tradeoff:

Slightly lower quality than paid embeddings
Slower on weak machines
Option B — OpenAI embeddings
Cost: extremely cheap
Rough estimate:
~$0.0001–0.0004 per document chunk

Typical project cost: $0.50–$2

Option A — Free (Local models)
Tools: Ollama (Llama 3, Mistral)
Cost: $0

Tradeoffs:

Lower reasoning quality
Slower
More setup
Option B — Cheap API (Best balance)

Using OpenAI or similar:

Simple runs: $0.01–$0.10 per full workflow
20–50 runs: still under $2–$4

💡 Biggest cost factor:

Multi-agent loops (CrewAI can call the LLM multiple times)
4. Zapier
Free plan includes:
Limited Zaps (usually 100 tasks/month)
Basic webhook support

Cost: $0

If you exceed:

Local (recommended)
Cost: $0
Cheap cloud (optional)
Render / Railway free tiers → $0

💸 Realistic Total Scenarios
🟢 Scenario 1 — Fully Free Setup
Local embeddings

Free Zapier tier

Total: $0

🔴 Scenario 3 — Fully API-based

⚠️ Where Costs Can Sneak Up

Be careful with:

1. Agent loops (CrewAI)
Each step = API call
3 agents × 3 steps = 9+ calls per run
2. Large documents
More chunks = more embedding + retrieval cost
3. Long outputs
Reports = more tokens = more cost
💡 Cost Control Tips
Limit agent runs
max_iter=2
Use small models
e.g., “mini” / “lite” models
Cache results
Don’t re-embed same documents
Reduce chunk size
Fewer embeddings
